# Админ-панель для лендинга — дизайн

Дата: 2026-06-07
Статус: на согласовании

## 1. Цель

Дать заказчику простую и понятную админ-панель (`/admin`), через которую он сам
редактирует основное наполнение сайта. Текущее тестовое наполнение не теряется —
оно переносится в базу и становится стартовым содержимым админки.

## 2. Принципы

- **Простота и понятность важнее полноты.** MVP охватывает основные разделы; редкие
  декоративные блоки пока остаются в коде.
- **Разделы админки = разделы сайта** — чтобы заказчику было очевидно «что где».
- **Загрузка фото — внутри карточки.** Никакой отдельной медиатеки: поле загрузки
  фото встроено прямо в форму записи (дом, проект). Загрузил → сразу привязано.
- **Разработка сейчас полностью локальная.** VPS нужен только для финального деплоя.

## 3. Объём (scope)

### Редактируется в админке (MVP)
- **Готовые дома** — фото, цена, площадь, участок, комнаты, санузлы, локация, статус,
  показать/скрыть, порядок.
- **Дома в строительстве** — название, этап, срок сдачи, локация, показать/скрыть, порядок.
- **Проекты** — фото, название, площадь, этажность, цена, срок, тег, описание,
  показать/скрыть, порядок.
- **Участки** — название, площадь, коммуникации, локация, показать/скрыть, порядок.
- **Цены/комплектации** — строки таблицы + подписи и цены трёх пакетов
  (тёплый контур / предчистовая / под ключ).
- **FAQ** — вопрос, ответ, порядок.
- **Настройки сайта** — телефон, ссылки мессенджеров (WhatsApp, Telegram, MAX),
  режим работы (часы), SEO title и description.

### Пока НЕ в админке (остаётся в коде, добавим позже)
Быстрый выбор, блок «Доверие», «Этапы», квиз, логотипы банков, тексты заголовков
секций. Причина: завязаны на иконки в коде или меняются крайне редко.

## 4. Стек и архитектура

- **Next.js (текущий проект, App Router)** — админка живёт в том же приложении в
  сегменте `/admin`.
- **PostgreSQL + Prisma ORM** — миграции и типобезопасные запросы. При переходе на
  MySQL меняется `provider` в схеме (до первой миграции) — выбор не теряется.
- **Авторизация:** один аккаунт администратора. Логин и **bcrypt-хэш пароля** в
  переменных окружения (`ADMIN_USERNAME`, `ADMIN_PASSWORD_HASH`). Сессия —
  подписанный httpOnly-cookie (секрет в `AUTH_SECRET`). `middleware.ts` закрывает
  `/admin/*` (кроме `/admin/login`) и admin-API. *Перед продакшеном при
  необходимости усилим (вынос в таблицу пользователей, смена пароля из UI).*
- **Хранение фото:** загрузка в `public/uploads/` на сервере, в базе хранится
  относительный путь. На VPS с Node читается/пишется напрямую и отдаётся статикой.
- **Публичный сайт читает контент из базы** через слой доступа к данным (серверные
  функции). Секции сайта уже Server Components — переход ложится естественно.

## 5. Модель данных (Prisma)

Общие поля у коллекций: `id` (cuid), `sortOrder` (int), `isVisible` (bool, default true),
`createdAt`, `updatedAt`.

- **ReadyHome**: `title`, `price`, `area`, `land`, `rooms`, `baths`, `location`,
  `status`, `image` (путь/URL) + общие поля.
- **Project**: `name`, `area`, `floors`, `price`, `time`, `tag`, `description`,
  `image` + общие поля.
- **BuildingHome**: `title`, `stage`, `finish`, `location` + общие поля.
- **Plot**: `title`, `area`, `utilities`, `location` + общие поля.
- **PriceRow**: `work`, `warm`, `pre`, `full`, `sortOrder`.
- **FaqItem**: `question`, `answer`, `sortOrder`.
- **SiteSetting**: пары ключ/значение (`key` уникальный, `value` text). Ключи:
  `phone`, `whatsapp_url`, `telegram_url`, `max_url`, `work_start`, `work_end`,
  `seo_title`, `seo_description`, `price_warm_label`, `price_warm_value`,
  `price_pre_label`, `price_pre_value`, `price_full_label`, `price_full_value`.

Аккаунт админа в базе не хранится (в `.env`).

## 6. Слой доступа к данным (публичный сайт)

- `app/lib/db.ts` — единый экземпляр Prisma Client (singleton, безопасно в dev).
- `app/lib/queries.ts` — функции чтения: `getReadyHomes()`, `getProjects()`,
  `getBuildingHomes()`, `getPlots()`, `getPriceRows()`, `getFaqItems()`,
  `getSettings()`. Возвращают только видимые записи (`isVisible`), отсортированные
  по `sortOrder`. Форма объектов совпадает с тем, что сейчас ждут компоненты.
- Компоненты секций получают данные из этих функций вместо импорта массивов из
  `app/content/landing.ts`.
- `app/content/landing.ts` сохраняется как **источник сид-данных** и место с
  типами/иконочными (пока некодируемыми) блоками.

## 7. Интерфейс админки

- `/admin/login` — форма входа (логин, пароль). Ошибка при неверных данных.
- `/admin` — дашборд: карточки-ссылки на разделы со счётчиками
  (например «Готовые дома: 5»).
- **Левое меню** со всеми разделами; шапка с кнопкой «Выйти».
- Для каждой коллекции:
  - **Список** записей с колонками-превью, кнопками «Редактировать», «Скрыть/Показать»,
    «Удалить» (с подтверждением) и управлением порядком (sortOrder; стрелки вверх/вниз).
  - Кнопка **«Добавить»** → форма создания.
  - **Форма** с понятными русскими подписями полей. У «Готовых домов» и «Проектов»
    в форме встроено поле загрузки фото с превью текущего/нового изображения.
- **Цены, FAQ, Настройки** — отдельные формы (FAQ и Цены — списком строк).
- Свои стили, чистый минималистичный вид в духе сайта. Без сторонних UI-библиотек.

## 8. Загрузка фото

- В форме записи поле «Фото»: выбор файла → `POST /api/admin/upload`
  (защищён middleware) → файл сохраняется в `public/uploads/` с уникальным именем →
  возвращается путь → подставляется в скрытое поле формы и показывается превью.
- При сохранении записи путь пишется в её поле `image`.
- Старое фото заменяется выбором нового. `next/image` отображает локальные пути
  напрямую.

## 9. Первичное наполнение (сид)

- `prisma/seed.ts` переносит всё текущее содержимое из `app/content/landing.ts`
  (5 готовых домов, 7 проектов, дома в строительстве, участки, строки таблицы цен,
  FAQ, контакты, режим работы, SEO) в базу.
- Фото с Unsplash остаются строками-URL (в `next.config.ts` Unsplash уже разрешён),
  локальные фото проектов — путями `/projects/...`.
- Запускается один раз — админка сразу заполнена реальными данными. Ничего не теряется.

## 10. Кеширование

- Чтение из базы делает страницы серверными. Чтобы сайт оставался быстрым,
  оборачиваем запросы в кеш и сбрасываем его при сохранении в админке:
  после любого create/update/delete вызываем `revalidatePath('/')`.

## 11. Разработка сейчас (без VPS)

1. Поднять PostgreSQL в Docker (одна команда).
2. `.env`: `DATABASE_URL` на localhost, `ADMIN_USERNAME`, `ADMIN_PASSWORD_HASH`,
   `AUTH_SECRET`.
3. `prisma migrate dev` (создать схему) + `prisma db seed` (наполнить).
4. `npm run dev` → сайт на `localhost:3000`, админка на `localhost:3000/admin`.

## 12. Деплой на Beget VPS (позже)

1. На VPS: Node + PostgreSQL (или MySQL — сменив `provider`).
2. Скопировать проект, прописать прод-`.env`.
3. `prisma migrate deploy` + `prisma db seed` (один раз).
4. `npm run build` и запуск через PM2 (`npm start`).
5. Папка `public/uploads/` персистентна на диске VPS.
   **Код приложения при этом не меняется.**

## 13. Риски и заметки

- Нужен именно **VPS с Node + БД**; статический хостинг/Netlify static не подойдёт.
- Запись фото в `public/uploads/` рассчитана на постоянный сервер (VPS) — ок.
- Auth в MVP упрощён (один аккаунт в `.env`); усиление — отдельный шаг перед продом.
- `.env` и `public/uploads/` добавляются в `.gitignore`.

## 14. Вне рамок этого этапа (на будущее)
